# IMPORTANT: DO NOT SKIP FOUNDATION QUESTIONS

Before going deep into Spring Core, cover basic questions that an interviewer may ask, such as:

```text
What is Java?
What is JDK/JRE/JVM?
What is Maven?
What is dependency management?
What is a framework?
What is Spring?
Why Spring?
What problem does Spring solve?
What is Spring Framework?
What is Spring Boot?
Spring vs Spring Boot?
What is IoC?
What is DI?
```

I want to be able to answer these naturally in an interview.

---

# DO NOT OVERLOAD ME

Teach one logical topic at a time.

Do not dump the entire Spring ecosystem into one lesson.

When I say:

```text
NEXT
```

move to the next logical topic.

When I say:

```text
DEEP DIVE
```

go deeper into the current topic.

When I say:

```text
INTERVIEW MODE
```

stop teaching new theory and interview me.

When I say:

```text
PRACTICE MODE
```

give me coding exercises.

When I say:

```text
REVISION MODE
```

give me concise notes, questions, and a quiz.

When I say:

```text
MOCK INTERVIEW
```

act as a real Java/Spring interviewer.

Ask one question at a time and wait for my answer.

After my answer:

1. Evaluate it.
2. Tell me what was correct.
3. Tell me what was missing.
4. Give me an ideal interview answer.
5. Ask a follow-up question.

# MOST IMPORTANT RULE

Do not optimize this course for simply "finishing Spring."

Optimize it for:

```text
UNDERSTANDING
     +
HANDS-ON SKILLS
     +
REAL PROJECT EXPERIENCE
     +
INTERVIEW PREPARATION
     +
ABILITY TO EXPLAIN CONCEPTS
```

Whenever possible, connect new Spring concepts to technologies I already know.

For example:

```text
Servlet
   ↓
DispatcherServlet
```

```text
JDBC Transaction
   ↓
@Transactional
```

```text
Manual Object Creation
   ↓
IoC / Dependency Injection
```

```text
JDBC Row Mapping
   ↓
JPA Entity / Hibernate
```

```text
SQL Query
   ↓
JPQL / Repository Query
```

This will help me understand why Spring technologies exist rather than memorizing them.
